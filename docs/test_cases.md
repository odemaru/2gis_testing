# Тест-кейсы: метод создания избранного места

- **Объект тестирования:** `POST /v1/favorites`, создание избранного места
- **Стенд:** https://regions-test.2gis.com/v1
- **Автор:** Гавриков Т. М.
- **Дата:** 24.08.2026

## Общие предусловия

1. Стенд доступен.
2. Получен сессионный токен: пустой `POST /v1/auth/tokens`, значение приходит
   в cookie `token`, срок жизни 2000 мс.
3. Токен запрашивается заново для каждой проверки, потому что общий токен
   успевает истечь между тестами.

## Формат запроса

Параметры передаются формой `application/x-www-form-urlencoded`:

| Параметр | Обязательный | Ограничения |
|----------|--------------|-------------|
| `title` | да | от 1 до 999 символов: латиница, кириллица, цифры, знаки препинания |
| `lat` | да | число от -90 до 90 |
| `lon` | да | число от -180 до 180 |
| `color` | нет | `BLUE`, `GREEN`, `RED`, `YELLOW`, по умолчанию `null` |

## Ожидаемая структура успешного ответа

`200 OK`, тело в формате JSON:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | integer | монотонно возрастающий идентификатор |
| `title` | string | название места |
| `lat` | float | широта |
| `lon` | float | долгота |
| `color` | string или null | цвет иконки |
| `created_at` | string | дата создания, ISO 8601 |

Ответ с ошибкой выглядит так: `{"error": {"id": string, "message": string}}`.

## Позитивные проверки

### ТК-01. Создание места с корректными данными

**Предусловие:** получен действующий токен.

**Шаги:**
1. Сформировать запрос со случайными корректными `title`, `lat`, `lon`.
2. Отправить `POST /v1/favorites` с токеном в cookie.

**Ожидаемый результат:**
- статус `200 OK`;
- тело соответствует схеме успешного ответа: типы полей, диапазоны координат,
  длина названия, формат `created_at`;
- `title`, `lat`, `lon` в ответе совпадают с отправленными;
- поля `id` и `created_at` есть в ответе, лишних полей нет.

### ТК-02. Необязательный `color` не передан

**Шаги:** отправить запрос без параметра `color`.

**Ожидаемый результат:** `200 OK`, в ответе `"color": null`.

### ТК-03. Все допустимые значения `color`

**Шаги:** повторить создание места для `BLUE`, `GREEN`, `RED`, `YELLOW`.

**Ожидаемый результат:** `200 OK`, значение `color` возвращается без изменений.

### ТК-04. Границы длины `title`

**Шаги:** создать место с названием длиной 1 символ, затем 999 символов.

**Ожидаемый результат:** `200 OK` в обоих случаях, длина названия в ответе
совпадает с отправленной.

### ТК-05. Границы диапазонов координат

**Шаги:** создать место для сочетаний `(-90, -180)`, `(-90, 180)`,
`(90, -180)`, `(90, 180)`, а также с нулём по одной из координат.

**Ожидаемый результат:** `200 OK`, координаты возвращаются без изменений.

> Сочетание `(0, 0)` в этот кейс не входит: на нём сервис отвечает `500`,
> проверка вынесена в [BUG-3](bug_report.md#bug-3).

### ТК-06. Монотонность `id`

**Шаги:** создать подряд три места одним токеном.

**Ожидаемый результат:** `200 OK` на каждом запросе, идентификаторы строго
возрастают.

## Негативные проверки

Во всех кейсах этого раздела ожидается статус `400 Bad Request` и тело вида
`{"error": {"id": ..., "message": ...}}` с указанным сообщением.

### ТК-07. Пустой `title`

**Шаги:** отправить запрос с `title=""`.

**Ожидаемое сообщение:** `Параметр 'title' не может быть пустым`.

### ТК-08. `title` длиннее допустимого

**Шаги:** отправить запрос с названием длиной 1001 и 5000 символов.

**Ожидаемое сообщение:** `Параметр 'title' должен содержать не более 999 символов`.

> Длина ровно 1000 символов вынесена в [BUG-1](bug_report.md#bug-1): сервис
> её принимает, хотя по документации не должен.

### ТК-09. Не передан обязательный параметр

**Шаги:** отправить запрос без `title`, затем без `lat`, затем без `lon`.

**Ожидаемые сообщения:**

| Параметр | Сообщение |
|----------|-----------|
| `lat` | `Параметр 'lat' является обязательным` |
| `lon` | `Параметр 'lon' является обязательным` |
| `title` | `Параметр 'title' является обязательным` |

> Для `title` проверяется только статус: в фактическом тексте есть опечатка,
> сверка текста вынесена в [BUG-4](bug_report.md#bug-4).

### ТК-10. Координаты вне диапазона

**Шаги:** отправить запрос со значением, которое выходит за границу
на 0.000001.

| Значение | Ожидаемое сообщение |
|----------|---------------------|
| `lat = -90.000001` | `Параметр 'lat' должен быть не менее -90` |
| `lat = 90.000001` | `Параметр 'lat' должен быть не более 90` |
| `lon = -180.000001` | `Параметр 'lon' должен быть не менее -180` |
| `lon = 180.000001` | `Параметр 'lon' должен быть не более 180` |

### ТК-11. Координата не является числом

**Шаги:** передать `lat=abc`, затем `lon=abc`, затем `lat=55,028254`
с запятой вместо точки.

**Ожидаемое сообщение:** `Параметр 'lat' должен быть числом`, для `lon`
соответственно.

### ТК-12. Недопустимый `color`

**Шаги:** передать `color=test`, `color=BLUEGREEN`, `color=` (пустая строка).

**Ожидаемое сообщение:**
`Параметр 'color' может быть одним из следующих значений: BLUE, GREEN, RED, YELLOW`.

> Значения в неверном регистре (`blue`, `bLuE`) сервис принимает, это
> вынесено в [BUG-5](bug_report.md#bug-5).

### ТК-13. Порядок проверки параметров

**Шаги:** отправить запрос, в котором некорректны сразу все параметры:
`title=""`, `lat=91`, `lon=181`, `color=test`.

**Ожидаемый результат:** возвращается ошибка по первому параметру в порядке
`title`, `lat`, `lon`, `color`, то есть
`Параметр 'title' не может быть пустым`.

## Проверки авторизации

### ТК-14. Выдача сессионного токена

**Шаги:** отправить пустой `POST /v1/auth/tokens`.

**Ожидаемый результат:** `200 OK`, в ответе cookie `token` с `Max-Age=2`.

### ТК-15. Запрос без токена

**Шаги:** отправить корректный запрос создания места без cookie.

**Ожидаемый результат:** `401 Unauthorized`,
`Параметр 'token' является обязательным`.

### ТК-16. Запрос с неизвестным токеном

**Шаги:** отправить корректный запрос с несуществующим токеном.

**Ожидаемый результат:** `401 Unauthorized`,
`Передан несуществующий или «протухший» 'token'`.

### ТК-17. Повторное использование токена

**Шаги:** получить токен и отправить с ним два запроса подряд, уложившись в
срок жизни токена.

**Ожидаемый результат:** `200 OK` на оба запроса.

### ТК-18. Истечение токена

**Шаги:** получить токен, выждать больше 2000 мс, отправить корректный запрос.

**Ожидаемый результат:** `401 Unauthorized`,
`Передан несуществующий или «протухший» 'token'`.

> Кейс не проходит: фактическое время жизни токена около 2700 мс,
> см. [BUG-2](bug_report.md#bug-2).

## Проверки найденных дефектов

Собраны в [`tests/test_known_bugs.py`](../tests/test_known_bugs.py). Каждый
тест проверяет поведение, которого требует документация, и помечен `xfail`
со ссылкой на пункт [баг-репорта](bug_report.md). Пока дефект
воспроизводится, тест отмечается как `xfail` и прогон остаётся зелёным. После
исправления дефекта тест перейдёт в `XPASS` и уронит прогон, сообщив об
изменении.

| Тест-кейс | Дефект |
|-----------|--------|
| `title` длиной 1000 символов отклоняется | [BUG-1](bug_report.md#bug-1) |
| Токен недействителен через 2000 мс | [BUG-2](bug_report.md#bug-2) |
| Координаты `(0, 0)` принимаются | [BUG-3](bug_report.md#bug-3) |
| Сообщение об отсутствии `title` без опечатки | [BUG-4](bug_report.md#bug-4) |
| `color` в неверном регистре отклоняется | [BUG-5](bug_report.md#bug-5) |
| `created_at` совпадает с временем сервера | [BUG-6](bug_report.md#bug-6) |
